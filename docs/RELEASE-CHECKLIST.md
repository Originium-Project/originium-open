`RELEASE_CANDIDATE` permits resolved decisions and individual gates with genuine evidence; every outstanding gate remains false with `PENDING`. `LOCAL_DRAFT` retains its strict all-pending behavior. `RELEASE_APPROVED` requires all eleven gates and resolved decisions, LICENSE, and exact actual HEAD/index/worktree validation. Machine checks verify consistency, not authenticity or legal sufficiency of evidence.

Use `scripts/check-local.sh` for structural validation, expected pending-approval rejection and all offline tests of a manifest that is not yet fully approved. For a genuinely approved committed candidate use `scripts/check-local.sh --require-approved`: a reviewed, data-only trusted launcher on the host verifies actual HEAD and index before constructing a bounded public-only Git projection; it has no process-count limit (`RLIMIT_NPROC` is host-user-wide) and runs at most one Git child at a time. The guard and all tests then run inside Bubblewrap against that same commit and the mounted working files, with the unchanged 64-process cap. No ordinary private Git directory is mounted into target execution, no bare-host guard runs, and no approval is automatically created. Projection tests inside the sandbox cannot demonstrate host fork behavior; run the approved mode once on the real host to check it.
